## Port Store 1.0.0

**Port Store** installs, updates and removes ports right on a Miyoo Mini or Mini Plus running
OnionOS (and on the Mini v4 and Mini Flip, not tried yet). No computer, no copying folders by
hand: pick a game, press A, play it from **Games → MiyooPorts**.

Port Store hosts no games. Its catalog, rebuilt every day, says where each port's author
publishes it on GitHub, which file to take and what of it goes where on the SD card; the Mini
downloads the file from its author and checks it against the catalog's SHA-256.

### Install

1. Download **PortStore-1.0.0.zip** below.
2. Unzip it to the **root of the SD card** (it contains `App/PortStore`; merge with the
   existing `App` folder).
3. On the Mini: **Apps → Port Store**.

Coming from 0.4.1 or 0.5.0: Port Store offers this update by itself. From an unzipped 0.3.0 or
0.4.0: unzip this release over it once.

### What it does

- **62 ports and apps** from their authors' own releases: all 12 native N64 games of
  [Miyoo64](https://github.com/mr-finster/miyoo64) (Mario Kart 64, Super Mario 64, Ocarina of
  Time, GoldenEye 007…), Undertale, Fallout 1 and 2, Half-Life, Tomb Raider, OpenRCT2, Balatro,
  Minecraft and apps such as Moonlight, Syncthing or Better WiFi. Ports Port Store cannot
  install yet are listed under More, with a link.
- **Games**, **Apps**, **Installed**, **Updates** and **More** tabs; genres (Select);
  pictures; newest first (R2); collections such as Miyoo64 under their own heading.
- **Several at once:** X marks ports, Start installs them one after another; on Updates,
  Select updates them all.
- **MiyooPorts:** every game is in a system of its own in Games, next to your consoles,
  whatever way its author packed it; Apps keeps only apps, and OnionOS's Ports its own games.
  Ports Collection is added by itself when a game needs it.
- **Your game files:** for games that need your own copy (a ROM, the game's data), the port's
  page says what goes where and checks it (N64 ROMs by checksum, in any byte order). Copy the
  files into `App/PortStore/import` as they are, and Start moves them into place. Started
  without them, a game says what is missing.
- **Updates:** the catalog is downloaded each time Port Store starts; updates of the ports and
  of Port Store itself are offered as soon as their authors publish them, and their number shows
  under Port Store's name in Apps. Port Store updates itself and starts again.
- **Without Wi-Fi:** Port Store lists the files it needs, with their addresses, in
  `App/PortStore/downloads/to-download.txt`; bring them on a computer into that folder.
- **Safe with your card:** files are unpacked and checked before anything is put in place;
  updates and removals touch only the files Port Store put there, never saves, settings or
  your game files, nor another port's files; nothing is written outside the card's own folders.

### New since 0.5.0

A full review of the code, and every finding fixed:

- An update that only changes the case of a folder name no longer deletes the new files (the
  SD card does not tell case apart); a release with two files landing on one path installs
  them as one; an install stopped half-way is recorded, so it is finished or removed cleanly.
- One entry Port Store cannot read no longer costs the whole catalog; catalog paths that
  would lead off the card are refused.
- Port Store can no longer remove itself; it no longer stays stuck on its busy screen after an
  unexpected error; the catalog downloaded on start waits for a running install.
- Files from `import` never go into a shared folder, and a ROM of another version you have is
  never replaced; a folder named in a port's needs is found too.
- A download left half done is never mixed with a newer release; a wrong file in `downloads`
  is set aside and asked for again; the file is kept for another try after "not enough space";
  a stalled download gives up after 30 seconds.
- Versions compare as meant (`1.2.0` after `1.2.0-rc2`, `1.2` = `1.2.0`); a release file
  uploaded again under the same tag is offered as an update.
- Smaller fixes: "offline" goes once the catalog downloads, long messages fit the screen,
  Cancel only where a job can stop, pages scroll no further than their end, the Port Store line
  in Apps is never left half written.
- The catalog build no longer stops on one broken release, checks what the device can read,
  keeps its cache true to re-uploaded files, and warns about a release published without its
  file. Recipes in pull requests are checked more closely.

### Known limits

- **OnionOS only**, on the Miyoo Mini family. The Mini v4 and Mini Flip (752×560) are laid out
  but not tried on the devices yet: reports welcome.
- **GitHub releases only:** a port must publish its files as a zip, tar, tar.gz or 7z release
  on GitHub. Releases made of several files, `.ipk` packages and layouts for other systems are
  listed under More, for installing by hand.
- **Your own game files** (for Undertale, Fallout, Half-Life, the Miyoo64 ROMs…) are yours to
  bring; Port Store does not provide them.
- Downloads need Wi-Fi (Mini Plus, Mini Flip) and the right date and time on the device (secure
  connections are checked).
- The number of updates in Apps is the one Port Store saw last time it ran.
- After Port Store updates itself, it starts again (on its own).
