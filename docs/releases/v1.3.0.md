## Port Store 1.3.0

Games that run on a shared runtime: Port Store installs the runtime with the first of them,
and keeps it while any of them is on the card. The first such runtime is
[love-mini](https://github.com/l0st0npl4net/love-mini), which runs LÖVE 11 games on the Mini.

### Install

1. Download **PortStore-1.3.0.zip** below.
2. Unzip it to the **root of the SD card** (it contains `App/PortStore`; merge with the
   existing `App` folder).
3. On the Mini: **Apps → Port Store**.

Coming from 0.4.1 or later: Port Store offers this update by itself.

### New

- **Ports on a runtime.** A port can say what it runs on (`requires` in its recipe, or in a
  porter's catalog). Installing it installs that first, when it is not on the card or has an
  update; the confirmation says so, with the size of the extra download. Marked ports and
  *update all* put a runtime ahead of the games that need it, once; a game whose runtime does
  not install is left out, not installed broken.
- **A runtime stays while it is needed.** Removing it says which installed ports run on it.
- `portstore install <id>` on the command line installs what a port requires first;
  `portstore remove <id>` refuses a runtime other installed ports need.

### For catalogs

- Recipes and porters' catalogs (Mixtape format) take `requires`: a list of port ids.
  Porters' catalogs also take `needs` (as a recipe's): a game the user owns can say which file
  of theirs goes where.
- A file check's `search` folders: a file the need names found there (where another port of
  the game kept it) is offered to move into place, as from `import/`. A game
  on a runtime owns its own folder (`Roms/PORTS/Games/<Runtime>/games/<Name>/`), and its
  shortcut's checks of the runtime's files are not asked of the user. The index build warns of
  a port that requires an id the index does not have.
- `index/check_recipes.py` no longer stops on a recipe whose newest release lacks its file.

### Balatro

Balatro now runs on love-mini, from the love-mini games catalog: the port by Producdevity
leaves the catalog. Its update moves nothing of yours: after it, put your **Balatro.exe** (or
Balatro.love) into `Roms/PORTS/Games/love-mini/games/balatro/` (from the old
`Roms/PORTS/Games/Balatro/`: on Balatro's page **Start** moves it there; or copy it into
`App/PortStore/import/`). Saves of the
old port are copied over on the first start, when love-mini has none of Balatro's yet.

### Known limits

- Removing the last game of a runtime leaves the runtime: remove it from its own page.
- Everything else as in 1.2.1.
